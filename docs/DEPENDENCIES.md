Exact shipping pin: SQLite **3.53.4 / 3053004**, official [amalgamation distribution](https://www.sqlite.org/download.html), [release history](https://www.sqlite.org/changes.html), [public-domain dedication](https://www.sqlite.org/copyright.html), SPDX **blessing**. Official 2026 amalgamation ZIP (2,946,650 bytes) was fetched over HTTPS; published SHA3-256 `628a44cfe82c66aed1ccbbe85a562d2e33ebe64b3288981ed76285612227934e` verified before extraction. [Provenance](../packages/core/vendor/sqlite/provenance.json) records exact unchanged sqlite3.c/h SHA-256; CMake/source/Windows-fallback gates verify them. Vendored source is distribution input, not a locally generated build artifact. Git -text preserves exact upstream bytes; only those two hashed files are exempt from authored formatting tests. No build or runtime network resolution occurs.

Security review used the official [CVE status](https://www.sqlite.org/cves.html) and current patch history before adoption. 3.53.4 includes upstream fixes after 3.53.2; this is not an exhaustive advisory-database or vulnerability-free certification. The application must accept possibly corrupt private DB bytes, so defenses include pinned current patch, STRICT/constraints/schema fingerprint, defensive/trusted-schema configuration, fixed SQL/bound parameters, no extension loading/shared cache/DQS, no attachments and metadata/SQL/VM/cache budgets. Preserve ongoing release advisory/SBOM review (G12 owner repository maintainer); update SQLite only through an isolated reviewed hash/version change. Source-hash bootstrapping from the official HTTPS distribution is not independent signature attestation.

CMake compiles the vendored C target with warnings-as-errors and sanitizers. Only vendor unused-parameter/unused-variable warnings are exempt under Clang/GCC, reflecting unchanged OS VFS interface/legacy probe code; all application warning flags remain unchanged. Upstream itself has MSVC warning pragmas; no broad project CRT macro or new project-wide suppression is added. Windows BCrypt randomness/flush primitives are OS libraries; no redistribution dependency. Core SHA-256 is a small FIPS 180-4 content-hash implementation verified against empty/abc/million-a vectors, not encryption/authentication or FIPS-module certification.

License/provenance/security and anticipated size were reviewed before adoption; these measured totals complete the local footprint evidence.
