# CPU working image and identity evaluation, version 1

Step 5 refines the frozen linear-sRGB CPU pipeline (ADR 0003), premultiplied alpha (PHOTO_ENGINE.md), and explicit-context lifecycle (ADRs 0009/0011). No new dependency or superseding architecture decision is needed.

## Input and orientation

Only an owned successfully decoded JPEG/PNG image handle can normalize. Shared C++ validates metadata, exact RGBA8 buffer length and transformed layout before allocation. Encoded dimensions and source orientation remain available through decode_query; working_query returns canonical dimensions/stride/orientation 1 and original orientation/profile type. Values 1-8 map exactly as encoded-image-v1.md: identity, horizontal reflection, 180 degrees, vertical reflection, transpose, clockwise 90, transverse, clockwise 270. Width/height swap for 5-8. Missing orientation defaults to 1 at admission; invalid explicit orientation rejects, never clamps. Originals remain byte-for-byte unchanged.

## Color and numerical interpretation

Profile absent means the frozen default sRGB assumption, not measured color provenance. Explicit PNG sRGB is sRGB-like. Embedded ICC is profile-present and normalization returns UNSUPPORTED (16), retaining original bytes/profile/digest rather than claiming a conversion. PNG gAMA/cHRM without explicit sRGB also defers (16), including nominal gamma 45455: a gamma annotation alone does not specify the sRGB piecewise transfer. With explicit sRGB, any supplied gAMA must equal 45455 and cHRM must equal the canonical integer chromaticities; contradictory annotations defer. Step 4 admission/decode behavior remains unchanged. Other private color metadata remains in the immutable original; full semantic profile interpretation is deferred.

Canonical memory is tightly packed native IEEE binary32 RGBA, linear sRGB/D65, premultiplied alpha. RGB applies the [sRGB inverse transfer](https://www.w3.org/WAI/WCAG21/Understanding/relative-luminance.html) to the encoded byte/255, then multiplies by alpha/255. Alpha stays linear. Alpha zero yields zero RGB; no hidden nonzero colors. No output/export transform or compositing is implemented. Fixed 256-entry binary32-rounded RGB and alpha tables avoid runtime libm/platform codec policy. Transfer table absolute error <3e-8; normalized components absolute error <6e-8 versus double formula. Orientation permutations and identity evaluation preserve float bits exactly. Ordinary IEEE nearest rounding is required; the implementation does not change caller rounding mode. Tables are immutable constants, not a mutable cache. No fast-math or fused chained arithmetic is used.

## Ownership, limits and execution

[working.h](../../packages/core/include/pixaura/working.h) is an additive, separately versioned API sharing the existing explicit decode context registry. Working values privately own float vectors and retain immutable encoded/profile provenance after source/decoded handle release. Identity evaluation consumes only a working handle and creates a separate bit-identical buffer. It executes no document operation, changes no revisions/SQLite, and cannot export. Duplicate requests independently consume budget; release uses decode_release. Query/copy uses caller-owned bounded outputs; no internal pixel pointer or codec object crosses C ABI.

Positive request limits may reduce defaults: width/height 16384, 8388608 pixels, row 262144 bytes, image 128 MiB. The lower pixel ceiling follows four binary32 components per pixel under the unchanged 128 MiB image ceiling. Transposition validates normalized dimensions against request limits. All products are checked: width*height, width*16, stride*height; exact byte size must fit size_t. Existing decode/context limits remain in force: shared aggregate payload/reservations 256 MiB by default, reducible at context init, and 64 total live source/decoded/working handles. Retained encoded/profile storage is counted once; decoded and working vector capacities independently count. Fixed object/control overhead remains additional as documented in ADR 0011, so payload caps are not a peak RSS claim.

Normalization uses one new output allocation and no heap scratch/intermediate transformed raster. Identity uses one new output allocation, no heap scratch. Pixel loop control is constant stack space and tables are fixed read-only 2048 bytes. The existing input and new output must simultaneously fit context admission; allocator failure is contained but is never the only resource bound. No scheduler, tiles, cancellation, memory-pressure adaptation, implicit cache or GPU objects exist in this foundation.

Context operations serialize under the existing context mutex; independent contexts execute concurrently. Read/copy and duplicate requests are safe under that policy. Owners must join/quiesce operations before destroy/free (ADR 0009); concurrent destruction is forbidden, not silently made safe by a mutex. Handles retain fresh lifetime identity, monotonic never-reused serial and kind checks. All failure paths preserve caller outputs and publish no partial working image. C++ exceptions are contained by the authoritative C boundary.

## Evidence and scope

Exhaustive asymmetrical pixel fixtures for all orientations, real JPEG/PNG admission/decode/normalization, independent C/JNI/Swift calls, fixed-seed 1024 bounded dimension/permutation cases, every transfer code, checked overflow/layout/buffer/profile/budget adversaries, allocation-site sweeps and concurrent ownership tests. Actual sanitizer execution remains mandatory. No editing tool, crop/resize, mask, GPU, compositing, export or AI is authorized here. Full profile conversion needs a separately approved dependency decision; Step 6 is not started.
