no example ID/key below is an actual product or transaction.

Apple: supply the real allowlisted product IDs/kinds and Sandbox/Production scope
through the optional `PixAuraVerifiedStoreV3` bundle dictionary: integer `version=3`,
`environment` exactly `Sandbox` or `Production`, and `products` mapping actual IDs
to `subscription` or `lifetime`. Missing/invalid configuration remains unconfigured.
Use the SAME `NativeEditorRuntimePoolV2.shared` resource owner; create its optional
`configuredStoreAdapter(capability:)` with the existing OS capability owner. Observe
actual verified StoreKit purchase/current-entitlement/update/restore paths. Native
COMMIT and exact-proof acknowledgment must precede protected signed-cache repair
and transaction.finish. Capture genuine signed test evidence locally and sanitize
store/device/account identifiers before independent review. Never upload photos or
signing material. Do not infer freshness or trusted current UTC from cached JWS.

Android: the optional application metadata string `ai.pixaura.store.v3` contains
an operator-owned JSON object with exactly `version=3`, `environment` (`SANDBOX` or
`PRODUCTION`), the approved verifier's PUBLIC canonical P-256 `publicKeySpki` encoded
as Base64, and `products` mapping actual IDs to `subscription` or `lifetime`.
Do not include a private signing key, account credential or endpoint in this value.
The default manifest contains no such fabricated configuration. The application
passes its configured verifier to the SAME editor runtime pool and optional
`GoogleNativeStoreOwnerV3`; it must not instantiate another editor/storage owner.
Use a scoped request: begin with a current OS capability snapshot, send ONLY the
allowed necessary store transaction metadata/native nonce to the independently
approved verifier, pass the actual signed response to accept, and close on every
cancel/error path. No network client or Billing runtime is activated by this
metadata-only interface. Authentic Billing SDK/sandbox execution waits for its
separate dependency/privacy and account/configuration prerequisites.

For both: record signature failures, wrong scope/key/nonce, pending/cancelled,
