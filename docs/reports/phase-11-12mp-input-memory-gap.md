## Cause and bounded corrective direction

`EditorContextV2` currently reads verified encoded bytes into an owned vector.
`OriginalReaderV2` then copies that vector while reserving the decoded RGBA8 image
and the frozen codec scratch maximum. Simultaneous encoded owners are particularly
expensive for incompressible images. Denial is the correct resource-policy response;
the implementation must remove the excess residency rather than bypass accounting.

A versioned file-backed source path is needed: bounded immutable verified source
access, a complete first-pass metadata/provenance validation, release of that pass's
encoded buffer, and bounded streaming decode into the existing RGBA8 owner. Preserve
codec settings, orientation, color/profile admission, strict malformed/truncated
input rejection and exact CPU numerical results. Retain the legacy byte-reader and
all public v1 ABI contracts. Do not alter protected codec/filesystem sources without
the required compatibility authority; prefer additive versioned adapters.

Tests must cover full-entropy RGBA/RGB PNG and JPEG, resource rejection/recovery,
read/storage faults, cancellation, source replacement/symlink attacks, decoder
parity, and aggregate ownership during replacement of an already-open document.
In particular, two simultaneously retained 12 MP source owners plus decoder scratch
can also exceed the shared budget. Application replacement must preserve the saved
old project and recover it after a failed replacement without requiring simultaneous
full image residency. No silent downsampling or weakening of the 12 MP requirement.

This remains executable engineering work. It is not a request to waive G8 and is
not evidence of completed Phase 11 engineering or production readiness.

## Corrective successor — 2026-11-18 local evidence

The finding is corrected locally for the reproduced input; final source/platform/CI
qualification remains pending. The additive managed-source factory transfers the
verified vector and its reservation instead of copying it. It reserves codec scratch
from the same aggregate budget, capped at the existing 32 MiB codec maximum. The
existing decoder explicitly accepts smaller scratch caps; settings and numerical
kernels are unchanged. Binary-sized reservation leases remain held throughout decode,
so there is no probe/reacquire gap and no allocation outside the aggregate owner.
Insufficient codec scratch still returns a resource failure, never reduced quality.

The earlier byte-reader constructor retains its accepted fixed-scratch admission
behavior, including the severe-pressure assertion. An intermediate regression of
that assertion is preserved in `codec-scratch-v2-native-test.log`; the corrected
managed-only implementation passes the unchanged six affected tests in
`codec-scratch-compat-test.log`. No frozen source or admission ceiling was changed.
