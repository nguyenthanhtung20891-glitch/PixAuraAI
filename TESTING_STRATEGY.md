# Verification architecture

Test contracts across modes and platforms. Unit tests: C++ deterministic kernels/domain, Kotlin/Swift reducers and adapters. C ABI tests compile both C and C++ callers; invalid version/null/undersized output and ABI layout tested. Shared golden fixtures test serialized operations and pixel output. Native CPU is numeric oracle with explicit per-operation tolerances for GPU/provider parity.

Integration: SQLite transactions/migrations/crash recovery; plan validation -> candidate -> approval; stale revision; cancellation; tile seams; source identity/export cleanup; model tamper/provider fallback. Fuzz image/project/plan inputs with strict resource bounds. ASan/UBSan on Clang host builds, platform sanitizer where supported. No arbitrary downloaded user photos in tests; fixtures synthetic or licensed with attribution.

UI: Compose instrumentation and XCTest/XCUITest cover three modes, undo/redo across AI/manual, app interruption, picker denial/cancellation, comparison and accessible controls. Offline tests disable network and optional runtimes. Device tests measure low/mid/high tiers, thermal/memory downgrade and actual accelerated provider. Emulators cannot certify GPU quality, memory budget or battery behavior.

Phase 0 tests verify documentation/links, source hygiene, build contract, C ABI safety and linkage. Node built-ins need no package installation. Windows compiles shared library, independent C caller and C++ tests with warnings as errors. CMake/CTest + sanitizer run on Linux/macOS CI; Swift Package tests import C core on macOS. Android JNI adapter is cross-compiled by NDK CI. These checks validate boundaries only; they do not prove a mobile application or GPU runtime exists.

Phase 0 sanitizer execution is also available locally through installed Ubuntu WSL: `bash scripts/check-sanitizers.sh` compiles the shared core and independent C/C++ tests with Clang ASan/UBSan, then CTest requires clean valid calls plus test-only deliberate heap overflow and signed-overflow diagnostics. The ASan probe intentionally lies about caller capacity to trigger a write inside the shared library; it is excluded from non-sanitized/application builds. The verifier requires the expected nonzero exit, exact diagnostic class, and shared-core symbol for ASan, and retains logs. Sanitizer runtime options use consistent exit codes per probe because ASan/UBSan share common options. An uninstrumented build cannot pass by accepting compiler flags.

Apple CI runs `bash scripts/check-apple.sh` on macos-26/Xcode 26.6: CMake core/C caller tests; macOS Swift package tests for layout, version and invalid arguments; unsigned iOS device package build; actual XCTest execution of the same Swift/C boundary on an available iPhone simulator. Only the boundary library/test bundle is built; no Phase 1 app exists. Node fixtures test simulator selection and referenced script/scheme consistency. actionlint validates workflow syntax locally. Xcode/simulator compilation and execution remain pending until the macOS job is observed passing.

Track coverage as guidance; require every safety invariant/error branch to have a behavior test, rather than gaming a percentage. Before implementing a milestone, define fixture expectations and budgets. A failing or skipped mandatory test blocks advancement. See QUALITY_GATES.md for applicability and evidence requirements.
