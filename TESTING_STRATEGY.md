# Verification architecture

Test contracts across modes and platforms. Unit tests: C++ deterministic kernels/domain, Kotlin/Swift reducers and adapters. C ABI tests compile both C and C++ callers; invalid version/null/undersized output and ABI layout tested. Shared golden fixtures test serialized operations and pixel output. Native CPU is numeric oracle with explicit per-operation tolerances for GPU/provider parity.

Integration: SQLite transactions/migrations/crash recovery; plan validation -> candidate -> approval; stale revision; cancellation; tile seams; source identity/export cleanup; model tamper/provider fallback. Fuzz image/project/plan inputs with strict resource bounds. ASan/UBSan on Clang host builds, platform sanitizer where supported. No arbitrary downloaded user photos in tests; fixtures synthetic or licensed with attribution.

UI: Compose instrumentation and XCTest/XCUITest cover three modes, undo/redo across AI/manual, app interruption, picker denial/cancellation, comparison and accessible controls. Offline tests disable network and optional runtimes. Device tests measure low/mid/high tiers, thermal/memory downgrade and actual accelerated provider. Emulators cannot certify GPU quality, memory budget or battery behavior.

Phase 0 tests verify documentation/links, source hygiene, build contract, C ABI safety and linkage. Node built-ins need no package installation. Windows compiles shared library, independent C caller and C++ tests with warnings as errors. CMake/CTest + sanitizer run on Linux/macOS CI; Swift Package tests import C core on macOS. Android JNI adapter is cross-compiled by NDK CI. These checks validate boundaries only; they do not prove a mobile application or GPU runtime exists.

Phase 0 sanitizer execution is also available locally through installed Ubuntu WSL: `bash scripts/check-sanitizers.sh` compiles the shared core and independent C/C++ tests with Clang ASan/UBSan, then CTest requires clean valid calls plus test-only deliberate heap overflow and signed-overflow diagnostics. The ASan probe intentionally lies about caller capacity to trigger a write inside the shared library; it is excluded from non-sanitized/application builds. The verifier requires the expected nonzero exit, exact diagnostic class, and shared-core symbol for ASan, and retains logs. Sanitizer runtime options use consistent exit codes per probe because ASan/UBSan share common options. An uninstrumented build cannot pass by accepting compiler flags.

Apple CI runs `bash scripts/check-apple.sh` on macos-26/Xcode 26.6: CMake core/C caller tests; macOS Swift package tests for layout, version and invalid arguments; unsigned iOS device package build; actual XCTest execution of the same Swift/C boundary on an available iPhone simulator. This script builds only the boundary library/test bundle; the separate Phase 1 script builds the app. Node fixtures test simulator selection and referenced script/scheme consistency. actionlint validates workflow syntax locally. Xcode/simulator compilation and execution remain pending until the macOS job is observed passing.

Phase 1 adds JVM navigation/restoration tests, instrumented real-JNI and Compose destination/recreation tests, Swift coordinator/restoration/probe tests, and simulator UI navigation. Tests use no photos. `tests/shells.test.mjs` checks permissions/backup policy, coordinator parity, pinned wrapper integrity and deterministic target/source wiring; these checks supplement native execution rather than replace it. `scripts/check-ios-shell.sh` builds both device configurations and executes app-hosted Swift/C ABI plus UI tests; `scripts/check-apple.sh` preserves all package/core gates. Native application shells CI executes Android instrumentation on Linux KVM and iOS tests on macOS. Android Espresso 3.7.0 is explicitly pinned test-only for Android 16 compatibility. Report physical TalkBack/VoiceOver walkthroughs separately; test compilation is not accessibility execution evidence.

Track coverage as guidance; require every safety invariant/error branch to have a behavior test, rather than gaming a percentage. Before implementing a milestone, define fixture expectations and budgets. A failing or skipped mandatory test blocks advancement. See QUALITY_GATES.md for applicability and evidence requirements.

Phase 2 Step 3 adds normalized SQLite/immutable-asset storage_test, a C storage consumer, bounded reader/writer/epoch tests, and nine abrupt child-process crashes without destructors. Known SHA-256 vectors and streamed multi-chunk tests verify content addressing; corrupt rows/schema/assets, migration/version rejection, rollback, BUSY/WAL budgets and checkpoint failures retain approved durable state. Test-only hooks compile independently and never enter shipping behavior. JNI/Swift native storage creation/reopen tests exercise platform integration; full document/asset behavior runs in host CTest on actual Windows/MSVC and macOS CI as well as Linux/ASan/UBSan. Physical power-loss/filesystem-device durability is not certified by process crashes. tests/persistence.test.mjs verifies exact upstream hashes/build/gate wiring; only those hashed vendor files are exempt from authored whitespace policy. See the [Step 3 report](docs/reports/phase-2-step-3.md).

Phase 2 Step 1 adds `node --test tests/document-contract.test.mjs`: fixed-ID canonical JSON, ordered stack replay/replacement, branch retention, reloadable redo, stale-base/ABA generation, version/parameter validation, duplicate/escaped keys, malformed UTF-8, reference and resource limits. The fixture and test-only oracle live under tests; no Node domain code ships. They are executable specifications for the future C++ implementation, not production parser/renderer/persistence evidence. The [contract test matrix](docs/contracts/image-document-v1.md) requires native C/C++/Swift/JNI fixture parity, handle ownership/allocation failures, sanitizer fuzz seeds, source-hash checks and crash injection when those paths are implemented. Existing gates are preserved; the new tests run in Windows/Linux and macOS Foundation source jobs plus shell source CI.

Phase 2 Step 2 adds CMake document_test, document_c_consumer and document_allocation_test to host/Apple/sanitizer checks and both Windows compiler scripts. The independent C consumer saves actual canonical output for cross-host comparison. Native tests cover history/session/branch semantics, bounded malformed inputs, ownership, concurrent release and exhaustive per-allocation failure sweeps. Negative sanitizer probes and failure injection remain test-only. Android instrumentation executes the approved fixture through JNI; Swift package tests execute its byte-identical bundled test copy through the C API. tests/native-document.test.mjs guards resource/build/CI wiring; the original oracle is still engineering-only. Apple CI wiring is not Apple execution evidence. New checks add no runtime dependency or model/pixel fixture.
