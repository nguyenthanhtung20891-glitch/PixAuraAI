# Mac host engineering measurements

Run `python3 scripts/benchmarks/mac-host.py` on the authorized Mac checkout.
Requires Xcode clang, CMake, Python 3 and macOS getrusage semantics. The harness
links the existing shared core and uses synthetic RGB PNGs generated by Python's
standard library. Generated fixtures, projects, builds and samples stay under
`build/phase-10.1-host`. Each invocation creates fresh project directories.
No dependency installation, signing, model, user image or GPU promotion occurs.

The script builds Release core with the repository's strict numerical flags,
compiles `mac-host.cpp`, then measures 2 warmups and 7 complete iterations per
size. Results include exact harness hashes and core source SHA. A dirty checkout
must be reviewed and accompanied by source digests before evidence is accepted;
`source_sha` alone does not identify uncommitted source. The published Phase 10.1
record explicitly binds unchanged product sources and the new harness hashes.

For exit-time leaks, use a new empty repository build directory for each run:

```
mkdir -p build/phase-10.1-host/leak-review-projects
/usr/bin/leaks --atExit -- build/phase-10.1-host/mac-host \
  build/phase-10.1-host/synthetic-3000x2000.png \
  build/phase-10.1-host/leak-review-projects
```

Timings are informational macOS CPU samples. Four-preview and 100-inspection
values are batch totals. RSS is cumulative process high-water in Darwin bytes,
including caller buffers; it is not a native lease total or admission ceiling.
Read the integrated successor report for exact scope, acceptance and limitations.
